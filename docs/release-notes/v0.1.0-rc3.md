# Prism v0.1.0-rc3 发布说明（预发布）

**中文摘要**：v0.1.0-rc3 是 v0.1.0-rc2 之后的**推荐预发布版本**——它把管理面板按设计系统重建（组件库、七状态控件、亮/暗双主题、
三维出口地球），把 intel 的采集节奏从"按上游"改成"按节点"，把仓库的质量门禁从"人工挑"改成"跑真实构建标签集的
零排除 lint 加冒烟测试并进 CI"，并修掉 5 处真实缺陷（其中一处是 e2e 夹具的端口复用，另一处是面板构建门禁存在结构性盲区）。
内核与依赖没有任何变化：`go.mod` / `go.sum` 与 rc2 **逐字节相同**（sing-box **v1.14.2**，sing 固定在同一 commit）。
本文件的每一条都来自 git 历史、代码与本机实测；凡是没能证实的都不写。

> **为什么是 rc3**：rc2 之后 main 上累积了 **32 个提交**，包含上面那批修复与重建。rc2 的二进制与镜像里没有这些内容，
> 所以用它部署等于用 32 个提交之前的代码；rc3 的意义就是让"下载 release 二进制 / 拉镜像"这条腿与 main 一致。
>
> **已经验证的**：CI 在干净 runner 上六步全绿（`make web` → 安装 golangci-lint v2.14.0 → `make verify` →
> `make lint-go` → `make backend` → `make smoke`）；`make verify` 覆盖 go vet + 单元测试 + `-race` + 协议矩阵 +
> 面板四项门禁；面板浏览器回归 `make test-ui` 在真实后端与真实 Chromium 上 **8/8**；发布流程彩排（`workflow_dispatch`
> 跑完全部构建与镜像构建、不发布不推送）；rc3 源码干净 clone 的构建、校验与冒烟。
>
> **尚未验证的**：真实服务器上的多日长跑、公网 TLS 证书链、生产负载特征。这三条从 rc2 结转，仍未做——它们只能在真机上做。
> 容器**运行**验证也仍是 rc2 的人工结论（本版发布流程覆盖镜像**构建**，运行需要 daemon，CI 没有）。

**事实来源**：本版本的内容是 `v0.1.0-rc2` 之后的全部 32 个提交（见文末「本轮提交」）。
行为与决策的权威文档是 `docs/ENGINE_DECISIONS.md`、`docs/MIGRATION_FROM_RESIN.md`、`docs/UPSTREAM_BASELINE.md`、
`docs/PROTOCOLS.md`、`docs/SECURITY.md`、`docs/deployment.md`、`docs/API.md`、`docs/PERFORMANCE.md`。

## 1. 本版要点（相对 rc2）

### 1.1 管理面板按设计系统重建

- **一套组件库取代手写控件**：`internal/api/web/src/components/ui/` 现在是页面上唯一的控件来源，`src/styles/design.css`
  是唯一的设计令牌来源（旧的 `theme.css` / `vibrancy.css` / `workbench.css` 与 `Card` / `DataTable` / `DialogSurface`
  等旧组件已删除）。规范写在 `internal/api/web/DESIGN.md`。
- **机械门禁而不是口头约定**：`check-kit.mjs` 三条规则扫全部 `.tsx`（本轮 52 个文件通过），`check-contrast.mjs`
  校验两套主题共 **86 组配色**均达 WCAG AA，`check-slop.mjs` 运行 61 项反模式检查（本地目标）。三项都进了 `make test-web` / `make verify`。
- **页面都落到同一套栅格**：`Page` / `PageHeader` / `Panel` / `Table` / `Readout` / `Tabs` / `Sheet` 等构成页面骨架；
  仪表盘新增三维出口地球（WebGL 不可用时回退平面地图）、流量曲线与延迟分布。
- **控件七状态**：默认 / 悬停 / 焦点 / 按下 / 禁用 / 加载 / 错误在组件内实现并逐项核对；提交类按钮统一带 loading 态。
- **暗色优先、亮色可选**：`ThemeSwitcher` 取代旧的 `ThemeMenu`；两套主题都由上面的对比度门禁覆盖。
- **死代码清零**：全 `src` 双向扫描（每个导出符号 + 每条 import 路径）后，删掉仅有的两个 0 引用文件
  （`components/ComingSoonPage.tsx`、`features/nodes/quality/QualityOverview.tsx`）。`IPPureReview` 是活的，
  它由 `QualityDetails.tsx` 装配。删除后复扫无新孤儿，组件库里也没有无人使用的原语。

### 1.2 intel 采集

- **配额门从"按上游"改成"按节点"**（`1f883fa`）：via-node 查询的节奏跟随目标节点而不是上游来源，同一个源服务多个节点时不再被上游级 QPS 门串行化；随后据此提高了节点工作池（`3679a1e`）。
- **429 只冷却一个节点**（`1ca9ffd`）：上游限流不再把整个来源打冷；同一提交让 via-node 来源不再自带配额。
- **节点抽屉不再整页空白**（`76c7cf9`）：抽屉里某个请求失败时页面保持可用。

### 1.3 修掉的真实缺陷

1. **e2e 夹具会复用回环端口**（`15d3f81`）：`freeLoopbackPort` 用 bind `:0` 读号后立即关闭，内核可以把同一个端口连续返回两次；
   `shadowtls-v3-shadowsocks-chain` 用例在同一进程里预留两个端口再交给同一个 sing-box 实例，第二个 inbound 报
   `bind: address already in use`（`-count=3000` 复现 1 次，127.0.0.1:44417）。修法是保留一个 **64 条的有界**最近端口窗口
   （无界集合会在窗口耗尽时把临时端口段吃光：实测反而产生 212 次失败），并把窗口判定抽成纯函数 `portWindowAppend`。
   修复后 `-count=3000` 零失败。这条与下面第 5 条的**上游**竞态是两回事：`address already in use` 是 Prism 自己的，
   `WARNING: DATA RACE` 指 `(*CachedConn)` 是上游的。
2. **面板构建门禁存在结构性盲区**（`8e935cd`）：`check-kit` 的第 2 条规则被 `isUiKit` 限定在 `ui/` 目录内，于是**页面级**的高度覆盖
   对它不可见，而页面恰恰是最容易绕过组件库的地方。把规则扩到全部 `.tsx` 后立刻报出 15 处（含第 8 份 `selectClass` 副本与 13 处 `h-7`），
   全部修掉；并补了两条会在违例时变红的测试锁定这条规则。
3. **两处边界不对**（`6c35df9`）：`portWindowAppend` 在 `limit < 1` 时会静默关闭检测、`limit < 0` 会切片越界，现加钳制并补 0/-1 用例；
   `inbound_demux.go` 的注释把接受错误分类说成 `Temporary()` 的转写，实际是它的**超集**（用真实 EMFILE 的
   `*net.OpError{Op:"accept", Err:*os.SyscallError{Err:syscall.Errno}}` 形状实测），注释改为真实描述，行为不变。
4. **文档里有三处已经不成立的说法**（`535ca96`、`ecce8f2`）：`SECURITY.md` 改引检查名而不是行号；
   `THIRD_PARTY_NOTICES.md` 的 sing-box 版本 v1.14.1 → v1.14.2；rc2 说明里的上游测试文件数 93 → **105**（与迁移文档、`PROTOCOLS.md` 对齐，GitHub 上 rc2 的正文也已同步）。
5. **新的 lint 门禁立刻抓到问题**（`f84fdc9`）：接入 `make smoke`（23 项离线端到端）与 `golangci-lint` 后，先修掉它们发现的
   `egress_test.go` 的 `newTestProbe` 按值捕获时钟（两次观测时间戳相同，原测试靠排序兜底假绿），改为指针后实测差正好 1 小时。

### 1.4 质量门禁：从"人工挑"到"跑真实配置且零排除"

- **lint 清掉 137 处**：11 个无调用者的死符号（`96e30fc`）、5 处已弃用 API 的真迁移（`bd596a2`）、58 处风格问题（`05e2d36`）、
  63 处未检查的错误返回（`ca64afb`）。
- **配置零排除**（`923a914`）：`.golangci.yml` 只启用 `errcheck` / `govet` / `ineffassign` / `staticcheck: all` / `unused`，
  除 `std-error-handling` 预设与 `node_modules` 路径外**没有任何按检查项的排除**——树是按现状通过的，不是靠抑制。
- **lint 用真实构建标签集**：`make lint-go` 与 `make backend` 用同一组 8 个标签，并在二进制缺失时**失败关闭**（不会静默变成空跑）。
- **5 处弃用 API 的迁移都做了等价性验证**，其中反代的 `Director` → `Rewrite` 用真实 `httputil.ReverseProxy` 双路径对拍：
  方法/路径/查询/主机/正文/头名集合完全一致，14 个身份头双方都不出现，`X-Forwarded-For` 计数为 0。
- **CI 与文档一致**：`CONTRIBUTING.md` 写明 CI 实际会跑的步骤，`make smoke` 与 `make lint-go` 都是 CI 步骤。

### 1.5 仓库标准化

`.gitattributes`（全部文本 LF，并 renormalize 了 55 个历史文件，索引里 CRLF 归零）、`.editorconfig`、`.golangci.yml`、
`CONTRIBUTING.md`、issue 表单与 PR 模板。行尾、缩进、提交与验证要求现在都写在仓库里，而不是靠口头约定。

### 1.6 发布与部署路径修复

- **容器镜像标签**：`docker-compose.yml.example` 原来指向 `ghcr.io/mycatxl/prism:latest`，而 `latest` **只在非预发布版本发布**
  ——实测 `latest` 取到 HTTP 404 `MANIFEST_UNKNOWN`，只有 `0.1.0-rc1` / `0.1.0-rc2` 存在，也就是说照着 README 抄一份
  compose 再 `docker compose up -d` 会失败。现在示例固定到具体版本号，并按仓库自己的文档口径（"pin a version tag"）说明理由。
- **发布产物带校验和**：每次发布除 5 个平台归档外，还上传 `SHA256SUMS.txt`，下载后可以先校验再落地。
- **发布流程可彩排**：`workflow_dispatch` 会跑完所有构建与镜像构建、不发布 release、不推送镜像，因此换流程不必先发一个公开版本。
  本版就是这样先彩排再打标签的。

## 2. 升级步骤

### 2.1 从 Prism 旧版本升级

数据目录（`PRISM_STATE_DIR` / `PRISM_CACHE_DIR` / `PRISM_LOG_DIR`）保持不变，迁移在启动时自动完成。

```sh
# 1. 先快照（在线，VACUUM INTO，无需停机窗口）
/opt/prism/scripts/prism-backup.sh backup --out /var/backups/prism --keep 7

# 2. 停服务
sudo systemctl stop prism

# 3. 更新二进制（源码方式；也可以直接替换 bin/prism）
cd /opt/prism && git pull && make build

# 4. 换端口/数据目录时才需要重跑部署脚本（它保留已有 .env）
sudo ./scripts/deploy.sh

# 5. 启动并确认
sudo systemctl start prism
./bin/prism check-config          # 有效配置，密钥打码
./bin/prism version               # 版本 / 提交 / 构建标签
```

- **本版相对 rc2 新增两个迁移，启动时自动应用**：state 库 `000015_platforms_add_node_criteria`（平台节点准入条件，
  对应面板上的 AND 语义筛选），intel 库 `000003_via_node_block`（via-node 来源封禁表）。数据目录位置不变，无需手工迁移。
- **没有环境变量或配置格式的破坏性变化**：`.env.example`、`scripts/deploy.sh`、systemd 单元与容器文件在本版都没有改动
  （唯一的容器侧改动是 compose 示例里的镜像标签，见 §1.6）。
- 建议升级前确认 `PRISM_ADMIN_TOKEN` / `PRISM_PROXY_TOKEN` 至少 16 字符：启动时会拒绝弱令牌
  （要沿用旧行为就显式设 `PRISM_ENFORCE_STRONG_TOKENS=false`）。
- 端口/接入点有变化时重新检查接入点的 `allow_management`：管理面、`/ui`、`/sub` 都受它约束。
- 容器方式：镜像与运行说明见 `docs/deployment.md` 的 Docker 章节。本版镜像由发布流程构建，运行结论沿用 rc2 的实测
  （Docker 28.5.1 / Compose v2.40.3，三条代理路径都在容器内跑通）。

### 2.2 从 Resin 迁移

与 rc2 相同，用法见 `docs/MIGRATION_FROM_RESIN.md`：

```sh
PRISM_STATE_DIR=/var/lib/prism PRISM_CACHE_DIR=/var/cache/prism \
  prism import-resin \
    --from-state /var/lib/resin \
    --from-cache /var/cache/resin \
    [--from-log /var/log/resin] \
    [--force]
```

## 3. 已知限制

这些是本版本**确认存在**的边界，不是待办清单（已在代码/文档中核实）：

1. **上游 sing 的 `(*CachedConn)` 数据竞争仍在，本版不掩盖它。** 纯上游复现器（不引入任何 Prism 包）在 `-race` 下
   报 8 次，栈精确指向 `common/bufio/cache.go` 的 `Read`/`Close`；Prism 侧零帧。pin 住的 sing 与上游 `dev`/`main`/`stable`
   的该段代码逐字节相同，即上游未修，而版本被 sing-box v1.14.2 锁定。触发条件是 `GOMAXPROCS=2` 下 `-count=100` 约 1/100。
   处置：`docs/PROTOCOLS.md` §10.11、`docs/UPSTREAM_BASELINE.md`、`docs/ENGINE_DECISIONS.md` D-5 三处记录；CI 命中即重跑，
   不在 Prism 侧加锁掩盖。要根治需给上游提 PR。
2. **mihomo 不引入带来的协议缺口**：SSR 存量、Snell v1–v3、kcptun、VLESS XHTTP（以及 AmneziaWG 等）只能被导入并
   在解析报告里以 `ENGINE_NOT_BUILT` 说明，不能用。重建条件见 `docs/ENGINE_DECISIONS.md` D-1 结尾。
3. **质量与情报数据源需要自备离线库。** DB-IP Lite / MaxMind GeoLite2 / IPinfo Lite 不随包分发；未下载前数据源返回
   `PROVIDER_UNAVAILABLE`，也不记录 ASN/地区证据（下载与许可说明见 `README.md` 与 `THIRD_PARTY_NOTICES.md`）。
4. **mihomo 导出的 `anytls` 需要较新的 mihomo**（v1.19.2 会报 `unsupport proxy type: anytls`，v1.19.31 正常）。
   这是客户端版本问题而非导出缺陷，结论与证据见 D-4。
5. **`docs/PROTOCOLS.md` 里 sing-box `1.14.1` 的表述是有意保留的历史区间说明**（D-3 记录的竞态修复版本范围），
   当前版本以代码为准：`internal/node/capabilities.go` 的 `SingboxVersion` 是 **1.14.2**。
6. **两个验证目标只在本地跑**：`make test-ui`（浏览器回归，需要 Playwright 的 Chromium）与 `make test-slop`
   （反模式检测器，需要外部引擎）。两者都不进 `make verify`，理由写在 `Makefile` 与 `CONTRIBUTING.md` 里；
   CI 覆盖的是源码级门禁（类型、对比度、组件库规则、面板配置测试）。
7. **容器运行时验证仍只有 rc2 那次人工结论**：CI 里没有 docker 步骤（每次构建都需要 daemon），
   本版发布流程只证明镜像能构建（多架构、可拉取），不证明容器能起。
