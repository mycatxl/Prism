# Prism v3.0.0 发布说明

**中文摘要**：v3.0.0 是 Prism 的第一个正式版本——它把 Resin 的单端口代理/控制面完整继承下来（包括全部 93 个上游测试文件，
例外见 `docs/MIGRATION_FROM_RESIN.md`），并在其上加入了自己的 intel 检测子系统、平台质量准入、导出与公开订阅、
定时轮换与审计日志。内核只保留 sing-box，锁定 **v1.14.2**（mihomo 按决策 D-1 **不引入**）。
本文件的每一条都来自 git 历史与代码；凡是没能证实的都不写。

**事实来源**：本版本的内容是提交 `0d0553b`、`ca8590a` 之后的全部提交（本轮共 7 个，见文末「本轮提交」），
加上这两个基提交本身。行为与决策的权威文档是 `docs/ENGINE_DECISIONS.md`、`docs/MIGRATION_FROM_RESIN.md`、
`docs/UPSTREAM_BASELINE.md`、`docs/PROTOCOLS.md`、`docs/SECURITY.md`、`docs/deployment.md`、`docs/API.md`。

## 1. 新增功能

### 1.1 构建与入口

- **单端口多协议入口**：一个监听端口同时承载 WebUI、管理 API、HTTP 正向代理、CONNECT、URL 反代与 SOCKS5，
  按首字节/目标形态分流（`cmd/prism/inbound_mux.go`；上游的 mux/demux 测试全部移植）。
- **多接入点**：`/api/v1/endpoints` 支持热添加/启停接入点，每个接入点独立开关管理面、代理、HTTP 正向、反代、SOCKS5
  与 `require_proxy_auth_info`；环境定义的默认接入点是只读的（`internal/service/control_plane_endpoint.go`）。
- **管理专用监听面**：`PRISM_ADMIN_LISTEN=host:port` 另起一个只服务 `/`、`/healthz`、`/api*`、`/ui*`、`/sub*` 的
  listener，代理流量永远不落在这个口上（`cmd/prism/admin_runtime.go`）。
- **子命令与部署**：`prism init`（一次性打印管理员令牌、`.env` 0600）、`check-config`（密钥全部打码）、`run`、
  `version`、`backup`、`restore`、`import-resin`；`scripts/deploy.sh` 生成 systemd unit（`NoNewPrivileges`、
  `ProtectSystem=strict`、只读 `ReadWritePaths`），`scripts/smoke.sh` 提供离线冒烟。
- **构建标签统一**：`Makefile` 的 `TAGS_FULL`、`.github/workflows/release.yml`、根 `Dockerfile` 与
  `.github/Dockerfile.release` 使用同一套标签，不含 `with_mihomo`；二进制把标签写进 `prism version`。
- **内嵌前端**：`//go:embed all:web/dist` 把工作台打进二进制；未构建前端时 `/ui/` 明确返回 503 + `make web` 提示。

### 1.2 持久化

- **三个 SQLite 库**：`state.db`（强持久：配置、平台、订阅、节点、租约、接入点、导出档案、审计）、
  `cache.db`（可重建）、`intel.db`（intel 证据/评估/队列/任务）。统一单写连接 + WAL + `busy_timeout=5000`，
  文件 0600、目录 0700，权限在每次启动时被修复（`internal/state/schema.go`、`internal/state/permissions_test.go`）。
- **迁移器**：state 库到 `000014_audit_log`、cache 库到 `000002_subscription_nodes_evicted`、
  intel 库到 `000002_via_node_budget`（`internal/state/migrations/`、`internal/intel/store/migrations/`）。
  旧库启动即自动升级，`import-resin` 导入后也会自动跑到同一版本。
- **重启恢复**：拓扑与粘性租约、可观测性数据、intel 任务的中途重启续跑（`cmd/prism` 的 bootstrap 重启测试）。
- **指标保留**：新增 `metric_*_bucket` 历史与保留策略，`metrics.db` 每 5 分钟分批裁剪，
  `PRISM_METRIC_THROUGHPUT_RETENTION_SECONDS` / `PRISM_METRIC_CONNECTIONS_RETENTION_SECONDS` /
  `PRISM_METRIC_LEASES_RETENTION_SECONDS` 决定窗口；API 会把超窗的 `from` 静默夹到窗口内（`internal/metrics/retention.go`）。
- **请求日志分库 + 事件**：滚动分库、payload 捕获与截断标记，请求记录带 `events[]`（路由建议与轮换回退）
  （`internal/requestlog/`、`internal/proxy/events.go`）。
- **审计日志**：`audit_log` 表 + 90 天/100000 条保留；只记录 2xx 的写操作，只记请求体键名，凭据路径参数不入库
  （`internal/api/audit.go`）。

### 1.3 协议与引擎

- **内核只有 sing-box，锁定 v1.14.2**（见 §3 的 D-2/D-3）。导入与构建覆盖 SS/SS-2022、VMess、VLESS（含 Reality/Vision）、
  Trojan、Hysteria/Hysteria2、TUIC、AnyTLS、SSH、Snell v4/v6、HTTP、SOCKS、WireGuard（endpoint）、
  OpenVPN/OpenConnect（endpoint）、ShadowTLS 串接，以及 Clash/Surge/sing-box/分享链接/`.ovpn` 多种输入格式
  （完整矩阵见 `docs/PROTOCOLS.md`）。
- **mihomo-only 类型（SSR、Snell v1–v3、kcptun、VLESS XHTTP 等）**：导入时被识别并**报告**，
  构建时以明确的 `ENGINE_NOT_BUILT` 失败，绝不静默丢弃。
- **解析报告**：每个被跳过的节点都有原因码与样本，`GET /api/v1/subscriptions/{id}/parse-report` 与订阅详情里的
  `parse_report` 都可查；报告本身有容量上限与脱敏（`internal/subscription/report.go`）。
- **探测失败可解释**：新增 `internal/node/probe_error.go`，节点的最后一次探测失败被分类记录为
  `last_probe_error{class,detail,at}`，平台 `explain` 与 UI 都能看到原因；probe 失败不再污染 `last_error`
  （后者只表示节点根本构建不出来）。
- **解析器修复**：hysteria2/trojan 的字段映射修正、QUIC 协议不再写入 `tls.utls`（此前会让 hysteria2/tuic 无法拨号）、
  端口跳跃与单位解析的回归用例。
- **路由与平台**：平台质量准入（fail-closed）、`allocation_policy`（P2C/随机/按域名延迟）、被动熔断与主动恢复、
  定时轮换（轮换墓碑避免立刻回到旧 IP，`internal/routing/rotation_tombstone.go`）、IP 负载统计。

### 1.4 intel 子系统

- **任务流水线**：`POST /api/v1/intel/jobs` 支持按订阅、平台、显式节点哈希或过滤器圈定范围；条目级状态机、
  失败重试、取消、SSE 实时进度（`/intel/jobs/{id}/events`，不用轮询）。
- **自动入队**：订阅导入后按 `auto_intel` 决定是否自动建任务；系统级开关 `intel_enabled`。
- **数据源与检测规则的可运维面**：`GET/PATCH /api/v1/intel/providers`（密钥只写、只回 `has_key`，改完立即对运行中的
  registry 生效）、`actions/resume`（清暂停与 429 冷却）、`actions/refresh`（立刻下载离线库）、
  `GET /api/v1/intel/checks` + `PATCH /api/v1/intel/checks/{id}`（逐条开关解锁检测，持久化为 `check:<id>`，
  `load_errors` 报告 `checks.d` 里加载失败的用户规则）。
- **匿名 via-node 代理检测**：新增匿名 via-node 检测通路（`internal/intel/providers/vianode.go`），
  预算按节点计（intel 库迁移 `000002_via_node_budget`），避免一个节点耗尽整轮额度。
- **批量范围过滤**：批量任务的范围现在支持 `protocol`/`engine`/`region`/`purity_band`/`verdict`/`ip_type`/`healthy`
  等键（`cmd/prism/intel_runtime.go` 的 `resolveIntelScope`、前端 `internal/api/web/src/features/nodes/intelScope.ts`），
  覆盖测试 `cmd/prism/intel_scope_filter_test.go`（463 行）。
- **解锁检测校准**：内置规则（chatgpt/claude/gemini/google_captcha/netflix/tiktok/youtube_premium 等）的判定条件与
  区域/出口校准重做（`internal/intel/checks/builtin/*.yaml`、`internal/intel/checks/region_test.go`）。
- **节点情报视图**：`/intel/nodes/{hash}`、`/intel/ip/{ip}`、`/intel/status`；`/nodes` 支持
  `purity_min/max`、`verdict`、`confidence_min`、`native`、`asn`、`country`、`check=<id>:<outcome>` 过滤与
  `purity_score`/`latency`/`assessed_at` 排序。

### 1.5 导出与订阅

- **导出**：`GET /api/v1/nodes/export` 支持 `singbox`、`mihomo`、`v2rayn`、`uri`、`csv`、`json` 六种格式、
  名字模板与「只导健康节点」，单次上限 5000 条，跳过明细带原因码（`internal/export/`）。
- **订阅档案与公开入口**：`/api/v1/export-profiles` CRUD + `actions/rotate-token`；公开的 `GET /sub/{token}`
  只存令牌的 SHA-256 摘要，**明文 URL 只在创建/轮换响应里出现一次**；未知令牌与已停用档案统一 404；
  自带限流（60 次/分钟/令牌 + 120 次/分钟/客户端 IP）；`v2rayn` 带 `Profile-Update-Interval`，
  `mihomo` 以内联 YAML 下发。
- **反代友好**：订阅 URL 的 scheme/host 取自请求（`X-Forwarded-Proto` + `Host`），放在 TLS 反代后面不需要额外配置。

### 1.6 前端

- 工作台页面补全：平台、订阅、节点（含详情抽屉与情报面板）、质量、**导出**、**检测任务（SSE 进度）**、
  **审计日志**、系统配置、请求日志与资源页（`internal/api/web/src/features/`）。
- 节点列表的批量检测按钮与 URL 过滤器联动，明确标注哪些过滤条件批量任务无法复现（会多覆盖节点）；
  节点抽屉的 IPPure 重新检测按钮恢复。
- 中英双语文案；浏览器回归脚本站内自检（`internal/api/web/scripts/check-ui-live.mjs`、
  `check-quality-ui.mjs`）。

### 1.7 运维与观测

- **部署**：`prism init` → `scripts/deploy.sh`（systemd）或 `docker compose up -d`；反代 + TLS 示例见 `docs/deployment.md`。
- **备份/恢复**：`prism backup`（`VACUUM INTO` 在线快照）/ `prism restore` 与 `scripts/prism-backup.sh`，
  恢复前拒绝在实例运行时执行（`docs/backup-restore.md`）。
- **迁移**：`prism import-resin` 原地接管 Resin 数据目录（§4.2）。
- **观测**：请求日志（含 payload 抓取与截断标记）、指标三套（实时环 / 历史桶 / 当前快照）、审计日志、
  `/api/v1/quality/status` 与 `/api/v1/intel/status` 的健康面板。
- **安全加固**：登录失败限流（10 次/分钟 → 封禁 5 分钟，仅失败计数、仅可信代理的 `X-Forwarded-For`）、
  `/sub` 独立限流、出站资源与解压炸弹上限、日志脱敏（`docs/SECURITY.md`）。
- **路由建议事件**：请求日志里的 `events[]` 记录轮换回退/同 IP 回退等建议，便于排查粘性问题。

## 2. 与 Resin 的偏差清单

差异只允许出现在下面 6 条里（X1–X6，与 `docs/plan/00-overview.md` §7 的清单一致）。

**权威位置说明**：X1–X4 的行为定义与逐条细节在 **`docs/MIGRATION_FROM_RESIN.md` §2**；X5–X6 的定义在
**`docs/plan/00-overview.md` §7**（与 `docs/plan/PRISM_PLAN_FULL.md` §7 相同）。下表是摘要，遇到分歧以那两份文件为准。

| 编号 | 偏差（摘要） | 开关 |
|---|---|---|
| X1 | 默认要求 `PRISM_ADMIN_TOKEN` / `PRISM_PROXY_TOKEN` 非空且至少 16 字符；`PRISM_ENFORCE_STRONG_TOKENS=false` 恢复 Resin 行为（弱令牌只在 UI 标记）。zxcvbn 弱令牌判定永远只标记、不拒绝启动 | `PRISM_ENFORCE_STRONG_TOKENS` |
| X2 | 空令牌（关闭该范围鉴权）必须显式允许，且监听地址需为回环，或另设不安全开关 | `PRISM_ALLOW_EMPTY_ADMIN_TOKEN` / `PRISM_ALLOW_EMPTY_PROXY_TOKEN`（+ `PRISM_ALLOW_INSECURE_LISTEN`） |
| X3 | 环境变量以 `PRISM_*` 为准，`RESIN_*` 作为兜底并打印一次弃用告警；`PRISM_QUALITY_*` 没有上游对应变量，不做兜底 | 无（总是兼容） |
| X4 | 请求头同时接受 `X-Prism-Account` 与 `X-Resin-Account`（同时出现时 Prism 优先），两者转发前都被剥离；所有错误响应同时带 `X-Prism-Error` 与 `X-Resin-Error`，取值相同 | 无 |
| X5 | 平台 `quality_policy` 为空时行为与 Resin 完全相同；非空时启用质量准入（fail-closed：无法证明合格就不放行） | 平台字段 `quality_policy` |
| X6 | 新增的后台检测会消耗节点流量 | 订阅 `auto_intel=false` 或系统配置 `intel_enabled=false` |

除这 6 条之外，Resin 的环境变量、请求头、错误响应头、`Platform.Account:Token` 身份、粘性租约、
熔断/恢复、请求日志与指标语义都保持可用。上游 93 个测试文件按 `docs/MIGRATION_FROM_RESIN.md` §4 的对照表移植；
未落地的例外（`internal/publicsource` 整个包、两个 public-source 配置用例，以及 `internal/inspection` 的 4 个测试
与 `internal/api` 的 2 个测试）在该文件文末逐条说明理由。

## 4. 升级步骤

### 4.1 从 Prism 旧版本升级

数据目录（`PRISM_STATE_DIR` / `PRISM_CACHE_DIR` / `PRISM_LOG_DIR`）保持不变，迁移在启动时自动完成。

```sh
# 1. 先快照（在线，VACUUM INTO，无需停机窗口）
/opt/prism/scripts/prism-backup.sh backup --out /var/backups/prism --keep 7

# 2. 停服务
sudo systemctl stop prism

# 3. 更新二进制（源码方式；也可以直接替换 bin/prism）
cd /opt/prism && git pull && make build

# 4. 换端口/数据目录时才需要重跑部署脚本（它保留已有 .env）
sudo ./scripts/deploy.sh

# 5. 启动并确认
sudo systemctl start prism
./bin/prism check-config          # 有效配置，密钥打码
./bin/prism version               # 版本 / 提交 / 构建标签
```
- 升级不需要手工迁移：启动（或 `import-resin` 导入后）由迁移器按版本号自动应用；state 库的新增迁移是
  `000010`–`000014`（平台质量与轮换、订阅导入选项、intel 数据源设置、导出档案、审计日志），
  cache 库与 intel 库的迁移同样自动完成。
- 建议升级前确认 `PRISM_ADMIN_TOKEN` / `PRISM_PROXY_TOKEN` 至少 16 字符：X1 会在启动时拒绝弱令牌
  （要沿用旧行为就显式设 `PRISM_ENFORCE_STRONG_TOKENS=false`）。
- 端口/接入点有变化时重新检查接入点的 `allow_management`：管理面、`/ui`、`/sub` 都受它约束。
- 容器方式：镜像与运行说明见 `docs/deployment.md` 的 Docker 章节，但**镜像尚未在具备 Docker daemon 的环境里构建验证过**（§5）。

### 4.2 从 Resin 迁移

一次性接管 Resin 的数据目录，平台、订阅、节点（哈希不变）、租约、接入点全部保留，旧客户端继续用
`X-Resin-Account` 也能保持粘性会话：

```sh
PRISM_STATE_DIR=/var/lib/prism PRISM_CACHE_DIR=/var/cache/prism \
  prism import-resin \
    --from-state /var/lib/resin \
    --from-cache /var/cache/resin \
    [--from-log /var/log/resin] \
    [--force]
```

- `--from-state` / `--from-cache` 必需；`--from-log` 会一并导入 `request_logs-<unix_ms>.db`（把上游的
  `resin_error` 列改名为 `prism_error`）；目标库已存在时必须显式 `--force`，旧文件会先改名为
  `*.pre-import-<时间戳>`。
- 检测到 Prism 仍在运行（pid 文件或监听端口）会**直接拒绝执行**，判活方式与 `prism restore` 一致。
- 导入后按 `prism run` / systemd 启动即可；容器示例与宿主机示例见 **`docs/MIGRATION_FROM_RESIN.md`** §1
  （该文件是 `prism import-resin` 的权威文档：用法、偏差清单 X1–X4、环境变量对照、上游测试对照表）。

## 5. 已知限制

这些是本版本**确认存在**的边界，不是待办清单（已在代码/文档中核实）：

1. **Docker 镜像从未在具备 daemon 的环境里构建或启动验证过。** `Dockerfile`、`.github/Dockerfile.release`、
   `docker/entrypoint.sh`、`docker-compose.yml.example` 都在仓库里，但 CI 的 `ci.yml` 没有任何 docker 步骤，
   只有打 tag 时 `release.yml` 会用 buildx 推送到 GHCR；本仓库的开发环境没有 Docker daemon，
   **没有构建过镜像、没有启动过容器**。使用前请先自己构建一次并确认容器到达 `(healthy)`——
   `docs/deployment.md` 的「Not built or verified in this environment」写明了同样的限制。**不要**把本版本描述成
   「已验证 Docker 部署」。
