# Prism v0.1.0-rc5 发布说明（预发布）

**中文摘要**：v0.1.0-rc5 修的是 rc4 里那个**肉眼可见**的毛病：1536 断点层的看板原本写死 1288×1024，
在 1536×1024 上恰好正确，窗口一大就贴在主列左上角——实测 1920×1080 只覆盖窗口 **72%**、右侧空 408px，
2560×1440 覆盖 **40%**、右侧空 1048px。现在 12 个槽位与 4 个 rail 锚点全部按画布百分比定位，
参考尺寸仍保持逐像素一致（**28/28 探针**在容差内），更大的窗口按比例长满（覆盖率 **95%**）；
顺带修掉 rail 底部状态块的一处真实差异（位置偏低约 114px，且参考图里它是竖向渐变而代码里是纯色）。
新增源码级门禁 `check:responsive` 并接入 `make test-web`（CI 会跑，且用两次注入违例证明它会红）。
内核与依赖没有任何变化：`go.mod` / `go.sum` 与 rc4 **逐字节相同**（sing-box **v1.14.2**，sing 固定在同一 commit），
本版**没有新增数据库迁移**。本文件的每一条都来自 git 历史、代码与本机实测；凡是没能证实的都不写。

> **为什么是 rc5**：rc4 之后 main 上只有 **1 个提交**，但它是**面板层**的修正——rc4 的二进制与镜像里那块看板
> 仍然是固定画布，用它部署等于把"看板挤在屏幕左上角"这个问题继续发给使用者。rc5 的意义就是让
> "下载 release 二进制 / 拉镜像"这条腿与 main 一致。
>
> **已经验证的**：CI 在干净 runner 上六步全绿（run `36839457483`，提交 `5d6871e`：`make web` → 安装
> golangci-lint v2.14.0 → `make verify` → `make lint-go` → `make backend` → `make smoke`）；本机
> `make test-web`（37 项面板测试、`tsc`、100 组对比度、组件库 54 文件、**新增的响应式门禁**）、
> `make test-slop`（反模式检测器，0 命中）、`make test-ui`（Playwright 浏览器回归，**8/8**）、
> `go test ./internal/api/... ./internal/docsguard/...`、`gofmt` 干净。1:1 复刻验收跑的是**真实二进制**：
> 1536×1024 暗色下 **28/28 探针在容差内**（其中 2 项为本版新增）、无横向滚动、控制台无错误；
> 响应式矩阵 **11 种窗口 × 深/浅两主题 = 0 失败**（360×640 手机竖屏、390×844、414×896、844×390、
> 768×1024、1024×768、1280×800、1440×900、1536×1024、1920×1080、2560×1440），登录页在每种宽度都不溢出。
>
> **尚未验证的**：真实服务器上的多日长跑、公网 TLS 证书链、生产负载特征（三条自 rc2 结转，只能在真机上做）；
> 容器**运行**验证仍是 rc2 那次的人工结论（CI 里没有 docker 步骤，本版发布流程只证明镜像能构建与拉取）。

**事实来源**：本版本的内容是 `v0.1.0-rc4` 之后的全部 1 个提交（见文末「本轮提交」），7 个文件 +557/−93。

## 1. 本版要点（相对 rc4）

### 1.1 看板随窗口生长，不再钉在左上角

- **根因**：1536 层里的画布是固定 `1288×1024`，而"1:1 复刻"的验收只在 **1536×1024** 这一个尺寸上跑过——
  在那个尺寸它恰好填满窗口，所以 26 项探针全绿，更大的窗口则暴露成"看板贴在左上角"。
- **改法**：12 个槽位与 4 个 rail 锚点的 `left/top/width/height` 全部换成画布百分比（百分比由实测像素现算，
  不是手打），看板本身改为绝对定位并保留 `max(100%, 1024px)` 的高度下限。字号、圆角、边框、内边距与
  固定的 248px 侧栏**仍用 px**：仪表盘是变宽，不是把截图放大。

| 窗口 | 修复前 | 修复后 |
|---|---|---|
| 1536×1024（参考尺寸） | 看板 1288×1024，空右 24 / 空底 37，覆盖 95% | 逐像素不变（28/28 探针） |
| 1680×1050 | 空右 168 / 空底 63，覆盖 70% | 看板 1432×1050，空右 27 / 空底 38，覆盖 95% |
| 1920×1080 | 空右 **408** / 空底 93，覆盖 **72%** | 看板 1672×1080，空右 31 / 空底 39，覆盖 **95%** |
| 2560×1440 | 空右 **1048** / 空底 453，覆盖 **40%** | 看板 2312×1440，空右 43 / 空底 52，覆盖 **95%** |

剩下的空隙是参考图**自身的内边距**按比例缩放的结果，不是贴角。短窗口（如 1536×700）下看板保持参考图的
1024 高度、主列滚动到最后一行，而不是把卡片压扁。

- **两个坑（都踩到过，都留下了守卫）**：
  1. 看板**必须绝对定位**。它的父级包装元素高度是 `auto`，`max()` 里那个 `100%` 因此解析不出来，
     整条声明被浏览器丢弃，看板连同 12 个槽位一起塌成 0 高（探针一度掉到 22/26）。
  2. rail 的状态块与会话页脚是**rail 卡片**的子元素，百分比基准是卡片高度 835 而不是整列 1024；
     用错基准会把它们整体上移约 118px（原先的绝对像素则偏低约 114px）。

### 1.2 rail 底部状态块的实测修正

按参考图自身扫描线（x=100）重新定位：状态块底边框落在 y814–815（2px 亮线），会话页脚是 y837–857 的
21px 均匀色带，据此把两处换算到卡片基准（62.874251% / 77.724551%）。同一组扫描线还证明状态块内部是
**竖向渐变**（`#142648` → `#1a3e6d`），而代码里是纯色——本版按实测补上。这两处现在是**新的探针点**
（`rail_status_lower`、`rail_footer_fill`）：rail 下半部过去是整块看板上唯一没有被任何探针采样过的地方。

### 1.3 新增源码级门禁：面板的 1536 层必须保持流体

`internal/api/web/scripts/check-responsive.mjs` 从源码侧检查该层：看板必须是绝对定位 + `height: max(100%, 1024px)`；
每个槽位与 rail 锚点必须是百分比；每个百分比必须换算回参考几何（±0.6px）；白名单之外的定位 px 与渐变里的
像素色标都要报错。已接入 `make test-web`（进而 `make verify`），所以**不装浏览器的 CI 也能拦住"画布又被写死"**。
落地前做了两次负向对照：把槽位改回 `left: 9px` → 2 条报错；把看板改回固定高度与 `position: relative` → 6 条报错；
恢复后 0 问题。

同一批测试修正：`check-ui-live.mjs` 的 rail 断言原本数的是 DOM 里的链接（`AppShell` 同时渲染两套导航变体，
由 `2xl` 断点互换，于是数到 24 而期望 12）。现在断言的是**使用者能点到的那一套** rail：仍会因缺少目的地、
重复链接或出现两个"当前项"而失败，并且在 1536px 下验证的正是板式 rail 本身。

### 1.4 界面之外没有其他改动

`DESIGN.md`、`internal/api/web/DESIGN.md`（记录流体画布规则与门禁行）、`Makefile`、`package.json`（门禁接线）。
没有配置键增删，没有环境变量改名，没有端点变化。

## 2. 升级步骤

### 2.1 从 Prism 旧版本（含 rc4）升级

数据目录（`PRISM_STATE_DIR` / `PRISM_CACHE_DIR` / `PRISM_LOG_DIR`）保持不变；**本版没有新增迁移**。

```sh
# 1. 先快照（在线，VACUUM INTO，无需停机窗口）
/opt/prism/scripts/prism-backup.sh backup --out /var/backups/prism --keep 7

# 2. 停服务
sudo systemctl stop prism

# 3. 更新二进制（源码方式；也可以直接替换 bin/prism）
cd /opt/prism && git pull && make build

# 4. 换端口/数据目录时才需要重跑部署脚本（它保留已有 .env）
sudo ./scripts/deploy.sh

# 5. 启动并确认
sudo systemctl start prism
./bin/prism check-config          # 有效配置，密钥打码
./bin/prism version               # 版本 / 提交 / 构建标签
```

- **面板变化对运维是零操作**：浏览器强刷一次即可（静态资源带内容哈希，旧缓存不会与新后端错配）。
- 本版**没有新增端点**；鉴权边界与 rc4 相同。
- 容器方式：`docker-compose.yml.example` 的镜像标签已固定到 `0.1.0-rc5`；`latest` 只在非预发布版本发布，
  所以在每个版本都是 `-rc` 的当下它并不存在（照抄示例时请用固定版本号）。

## 3. 已知限制

这些是本版本**确认存在**的边界，不是待办清单（已在代码/文档中核实）：

1. **上游 sing 的 `(*CachedConn)` 数据竞争仍在，本版不掩盖它**：纯上游复现器在 `-race` 下报 8 次，
   Prism 侧零帧；pin 住的 sing 与上游 `dev`/`main`/`stable` 该段逐字节相同。触发条件是 `GOMAXPROCS=2` 下
   `-count=100` 约 1/100，CI 命中即重跑。要根治需给上游提 PR（对外动作，等操作者点头）。
2. **参考图复刻有两处折叠与三处真实残差**：折叠（实例健康、节点延迟分布）与残差（J 的内容差 Δ18.6、
   E/F 的玻璃亮度差 Δ11.8/8.4、H 五行相对参考图恒定 3px 偏移）都记在根目录 `DESIGN.md` 的 1536 板一节里，
   连同数值。rail 下半部的状态块差异已在本版修掉并纳入探针。
3. **浅色主题在 ≥1536 没有参考图可比对**：参考图只有暗色一套，浅色用的是设计系统自身的表面；
   默认主题是暗色。若要求浅色也逐像素对齐，需要一份浅色参考图。
4. **mihomo 不引入带来的协议缺口**：SSR 存量、Snell v1–v3、kcptun、VLESS XHTTP 等只能被导入并在解析报告里以
   `ENGINE_NOT_BUILT` 说明；重建条件见 `docs/ENGINE_DECISIONS.md` D-1。
5. **质量与情报数据源需要自备离线库**（DB-IP Lite / MaxMind GeoLite2 / IPinfo Lite 不随包分发）。
6. **mihomo 导出的 `anytls` 需要较新的 mihomo**（v1.19.2 报 `unsupport proxy type: anytls`，v1.19.31 正常），见 D-4。
7. **两个验证目标只在本地跑**：`make test-ui`（需要 Playwright 的 Chromium）与 `make test-slop`（需要外部检测器引擎）；
   CI 覆盖的是源码级门禁（含新增的 `check:responsive`）。
8. **容器运行时验证仍只有 rc2 那次人工结论**。
