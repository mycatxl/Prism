# 节点质量与界面复审

2026-09-08，依据用户对评分、分类、重复导航、设置页和全站贴边问题的反馈。实施与验收进行中。

## 数据口径与实施决定

当前节点分数来自 [ProxyCheck v3](https://proxycheck.io/api/)，风险越低越好。主代理已复核 v3 官方 0–25、26–50、51–75、76–100 的处置建议；它们还取决于 anonymous 标志，并非网站通过率。现有 Go 分档已经使用这四档，不能误报为仍在使用 v2 的 33/66 分界。

用户最新确认的分工：**IPPure 为纯净度/风险主来源，ProxyCheck 补充网络用途和匿名特征**。采用明确标注的 **Prism 展示规则 v1：纯净度参考分 = 100 − IPPure fraudScore**，同屏保留 IPPure 原始风险。分档为 95–100 极度纯净、90–94 纯净、80–89 较纯净、60–79 一般、0–59 风险较高。边界是产品分档，不是供应商官方评级、统计概率或网站通过率。ProxyCheck 风险分只留在来源详情；没有有效 IPPure 结果就不生成主分。高分与 VPN/Tor 等标记并存时保留原分并单独提示复核，不混分、不给负面证据平均降权。

ProxyCheck v3 官方网络用途为 Residential、Business、Wireless、Hosting、null。补足企业和无线网络，保留原始分类；Wireless 包含蜂窝和卫星，不能直接标成移动蜂窝。VPN、代理、Tor、机房标志等与网络用途分开展示；节点连接协议从配置的真实 type 读取。绝不依据节点名猜住宅、原生、双 ISP 或静态地址。

[IPPure 官方 API](https://ippure.com/MyIP-Info-API) 返回调用者出口，不能传任意 IP 查询。[FAQ](https://ippure.com/faq.html)明确 fraudScore 越大风险越高，IPv6 不计算；未提供权威的“95–100 极度纯净”阈值。实现节点上的低频、按需复核，经该节点 Outbound 请求固定官方 HTTPS 接口，展示实际出口、住宅属性和原生/广播信息。非住宅布尔值不自动等同机房，机房用途由 ProxyCheck 补充。核对本次 IP 与节点记录及返回时的当前出口；不匹配结果只展示给本次请求，不附着到节点。已匹配结果在内存中供同出口节点临时复用 24 小时，最多 512 条；过期结果额外保留 24 小时用于提示，重启后清除。有效期是本地展示策略，不是来源保证。复核不参加自动队列、不批量扫描、不落库；全实例一次并发、至少一分钟间隔，失败也消耗间隔并遵守更长 Retry-After。

[IPPure 条款](https://ippure.com/terms-privacy.html)限制未经授权的高频/批量访问、系统性存储和规避限制；公共 API 文档明确允许调用当前 IP 的接口。按需单次调用与后台批量数据源需区分。没有公开数字配额，不宣称无限免费。

对照 [ipapi.is](https://ipapi.is/free-tier.html) 和 IPQS：前者免费账户 1,000 次/日、匿名仅 30 次且简化字段；后者免费 1,000 次/月及 35 次/日。没有独立对照能证明它们更准确。ipapi.is 的 ISP/教育/政府等是机构分类，其机构/ASN 滥用比例不是当前 IP 纯净度。保留 ProxyCheck 自动特征检测和 AbuseIPDB 可选举报证据，IPPure 按需提供主分。

Tor 细分使用 [Tor Project Onionoo 的 CC0 公共资料](https://metrics.torproject.org/onionoo.html)，不将第三个商业风险分引入组合。后台按需刷新完整公共名录，每小时检查一次，不向该服务发送库存 IP。`exit_addresses` 表示最近 24 小时观察到的实际出口；`or_addresses` 与 Guard 标志用于标出中继和入口守卫资格，不能把 Exit 标志直接当作 OR 地址就是出口。私有网桥地址不公开，未列于资料不代表未使用 Tor。响应有大小、条目数和新鲜度上限，失败保留未过期资料。

官方原文与本次单次公开样本保存在 `/tmp/prism-quality-reaudit/`。Reddit/Linux.do 反馈只能证明有误报疑问和分数方向混淆，不能据此宣布准确率胜者。X 索引补查受限，没有新增可靠推文。

## 界面方向

保留已确定的深蓝导航 `#111b31`、浅色画布 `#f2f5fb`、白色工作区、正文 `#15213c`、动作蓝 `#256be6`。Manrope/Sora 和现有中文字体保持一致。数据、字段、表头左对齐，分数带清晰来源；普通面板 24px 内距，手机 18px，分组间 24px。减少重复卡片与解释性口号。

节点池是唯一节点工作入口，线路与按出口去重的记录在同页切换；移除独立“出口质量”导航，旧链接保留参数迁移。表格收拢为六列：节点身份/状态/协议，出口/网络用途/地区，IPPure 纯净度，网络特征/综合结论，参考延迟，详情操作。来源状态与预算归入系统配置的“质量与数据源”。

系统配置采用分类卡片入口，点击后仅展示该类别。父级统一保存草稿，切分类不丢修改；保存全部更改的范围明确。高级 JSON 使用明确的应用步骤，不能静默覆盖之后的表单修改。非法草稿仍属于未保存状态。

```text
节点池                 系统配置
线路 | 出口记录         分类卡片网格
筛选 / 统计 / 工具      → 选中分类的字段与只读参数
节点表格 → 详情          → 返回分类；草稿继续保留
          评分 / 类型    保存全部更改 / 变更预览
          IPPure 复核
```

贴边根因已经定位：workbench.css 的旧扁平样式把十二类卡片改为 `padding:16px 0`，vibrancy.css 恢复边框和底色却没有恢复内距。修复共用的业务面板规则，同时逐页检查表格、嵌套卡片、弹窗与手机，避免给全部 `.card` 盲加 padding。

## 验收范围

- 分数边界与缺失值、冲突和举报复核；Business/Wireless 映射及数据库旧证据迁移。
- IPPure 必须经选中节点、固定目标、有限响应、无重定向/直接回退；限流、取消、格式错误、IPv6 和换出口结果。
- 节点与出口视图分页隔离；旧质量深链可继续打开。
- 设置分类切换保留草稿、非法草稿提示、JSON 应用、统一保存和静态只读。
- 桌面/手机、浅深色下的设置、GeoIP、订阅、平台、规则、接入点、日志、节点、登录及浮层截图和实际内距。
