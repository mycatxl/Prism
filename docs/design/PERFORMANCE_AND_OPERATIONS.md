# 个人版性能、测试与运维

状态：设计基线，数值为初始预算或测试门槛，不是已完成能力。个人版优先保证转发热路径稳定，再提高检测吞吐。

## 1. 性能原则

1. 代理路由只访问内存快照、分片集合和原子状态，不查询 SQLite、GeoIP 下载、信誉服务或管理 API。
2. 标签、质量和平台筛选在冷路径预计算；策略变化以版本发布和增量通知更新视图。
3. 所有网络输入、队列、worker、连接、缓冲和日志都有上限。超限排队、降速或拒绝，不无限创建 goroutine。
4. 数据库只由 StateEngine 写入；批量事务和 dirty set 合并更新。
5. Outbound 分为冷库存、温摘要和有界热实例；不能为百万库存永久初始化百万个 sing-box Outbound。

管理面板默认监听 `127.0.0.1:1262`，后端 API/代理监听单独配置（Resin 兼容默认 2260）。改为局域网或公网必须显式配置并保持认证；面板开发及静态服务均不替代 CONNECT/SOCKS 等代理 listener。

## 2. 初始预算

这些参数必须支持配置并在压力测试中重新确定：

| 资源 | 初始值 | 超限动作 |
|---|---:|---|
| 管理请求体 | 1 MiB | 413 |
| 订阅压缩输入/解压结果 | 8/32 MiB | 拒绝并保留旧订阅 |
| 单批导入节点 | 50,000 | 分批继续或报告剩余 |
| 健康探测 worker | 32 | 到期队列延后 |
| 质量探测 worker | 8 | 来源限流和退避 |
| 质量任务队列 | 4,096 | 合并相同 IP 任务，超限告警 |
| 单来源并发 | 2 | 等待或退避 |
| 认证前握手 | 5 秒 | 关闭连接 |
| 代理最大并发 | 配置值，默认 1,024 | 拒绝新连接 |
| 单连接空闲超时 | 90 秒 | 关闭空闲连接 |
| 单 listener 待处理连接 | 配置值，默认 4,096 | TCP 层拒绝/退避 |
| 日志队列 | 8,192 | 丢弃普通日志并计数 |
| 平台标签规则 | 64 条，每条 1,024 字节 | API 校验失败 |

初始值针对个人单机起点，不代表百万节点和高并发的结论。将每次修改记录在配置版本和基准报告中。

## 3. 检测调度

健康、出口、质量和指定目标检测使用独立有界队列。调度器按 `next_run_at` 取任务，使用 jitter、优先级和 per-node 去重。正在使用、出口即将过期、新节点和平台当前急需的线路优先；长期未使用的冷库存按保底比例推进，避免永久饥饿。

平均并发近似为 `C = (A/T) * L`，其中 A 是周期任务数、T 是周期、L 是平均耗时。失败任务的耗时接近 timeout，需把重试、DNS、TLS 和带宽纳入预算。任务不按节点数启动 worker。

每个数据源使用 token bucket 限速、最大在途请求、Retry-After 上限和指数退避。429、认证失败、格式错误和超时分类处理；同一 IP/来源/profile 的任务合并。外部查询失败不阻塞代理，证据到期后按平台 unknown 策略处理。

通过节点做出口探测时，每条线路确实需要自己的代理请求；相同出口只能复用 IP 信誉查询，不能复用线路连通性和健康结果。探测 HTTP client 必须设置连接、响应头、响应体、TLS 和总超时，并限制响应字节。

## 4. 运行态和容量档位

定义 `N` 为库存节点配置数、`A` 为需要周期检测的线路数、`U` 为独立出口 IP 数。SQLite、内存、网络和 worker 预算分别按三者估算。

个人版优先支持 10 万库存，峰值回归覆盖 30 万库存；100 万只验证冷库存。必须通过分批导入、索引构建、冷启动、订阅刷新、平台重建、质量任务入队、WAL 增长和备份恢复测试。几十万活跃 Outbound、几十万并发连接和短时间完成全量检测不是默认承诺。

热运行态只保留当前平台候选摘要、近期任务线路、租约命中线路和有限备用线路。Outbound 按需创建并合并同节点并发创建；空闲淘汰关闭连接池但不影响活动连接。节点状态更新采用 generation/CAS，旧检测结果不能覆盖新出口。

## 5. 测试矩阵

| 层级 | 必测内容 |
|---|---|
| 单元 | 标签 ANY/MUST/MUST_NOT、区间边界、IP 规范化、评分归并、任务退避、lease CAS |
| 组件 | 导入格式、订阅 diff、节点去重、出口分组、平台视图、SQLite migration |
| 协议 | HTTP、CONNECT、SOCKS5 CONNECT、反向代理、WebSocket、半关闭和取消 |
| 安全 | 鉴权、CSRF、目标地址、DNS 重绑定、输入上限、secret 脱敏、路径隔离 |
| 恢复 | WAL、脏集合、任务 lease、过期证据、磁盘满、崩溃恢复和备份 |
| 并发 | `go test -race`、路由竞争、视图发布、重复检测、撤销与在途连接 |
| 压力 | 64/128/256 探测并发、代理 p50/p95/p99、连接数、FD、内存、GC、WAL |
| 长稳 | 24 小时订阅刷新、质量任务、连接建立/关闭、日志滚动和内存曲线 |

基准报告至少包含硬件、Go/sing-box 版本、节点配置大小、节点协议分布、目标 URL、并发、超时、成功率、p50/p95/p99、内存峰值、FD 峰值、数据库大小和任务积压。

## 6. 可观测性

指标分为代理、节点、检测、数据库和资源五类：请求数/成功率、连接建立失败、转发字节、健康节点、独立出口、平台候选、任务延迟/积压、provider 429、WAL、写队列年龄、日志丢弃、内存、GC、FD、goroutine 和 listener 拒绝。

日志采用结构化字段和 request ID。secret、认证头、订阅 token、目标 query 和原始节点密码默认脱敏。控制面提供任务状态、节点排除原因和检测来源，但不在数据面回显内部错误细节。

## 7. 运维与发布

启动检查：目录权限、数据库迁移、密钥可读性、listener 冲突、默认绑定地址、token 强度、探测端点和依赖版本。若安全配置不完整，代理 listener 不启动。

停止顺序：先停止新连接和调度 -> 等待或按超时关闭代理 -> 停止探测 -> flush dirty set 和日志 -> 关闭数据库。强制退出后下次启动执行一致性修复。

发布采用可复现构建：锁定 Go、sing-box、构建标签和前端依赖，生成版本、提交、构建时间、依赖和许可证清单。开源产物保留 Resin 版权与 MIT 许可；sing-box 依赖的 GPL-3.0-or-later 要求按实际发行形态提供对应源码和许可证，发布前完成法务核对。

发布门槛：功能、race、安全、恢复、协议矩阵、依赖扫描和压力基准通过；任何认证绕过、SSRF、secret 泄漏、旧结果串用、数据损坏或无界资源增长阻断发布。
